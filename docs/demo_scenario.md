# デモシナリオ（約15分）

事前準備: `sql/98_reset_demo_data.sql` で業務データを初期化し、Snowsight でアプリを一度開いてウェアハウスを起動しておく。
`samples/` の4ファイルを手元に用意する。

| 時間 | 画面 | 操作 | 伝えるポイント |

| 0:00 | — | 背景説明：取引先ごとにバラバラな発注書（A/B/Cを並べて見せる） | 書式が違う・項目名が違う・コードが違う・スキャン |

## 想定問答

- **AIが間違えたら？** → 業務ルール検証で ERROR/WARNING として検出し、人が修正。修正は監査ログに残る。スコアは参考値。
- **税率は？** → コードに埋め込まず `SNOWVILLAGE_TAX_RATES`（税区分×適用期間）から判定。税率ごとに1回切り捨て。
- **確定後に訂正版が来たら？** → 別ファイルで同じ発注番号が来た場合はまず ERROR で止める。取引先に確認できたら
  「訂正版として確定」で、理由（必須）を記録したうえで元の確定受注を SUPERSEDED にし、訂正版を確定する（差分・理由は監査ログ）。
  同じ受付の再読み取りは新しい版（DRAFT）を作成し、確定すると旧版は SUPERSEDED になる。
- **費用は？** → X-SMALL・60秒自動停止。AI_EXTRACT はページ数課金。Query ID でクレジットを追跡可能。

## 抽出失敗の実演（任意）

画面での障害注入は用意していません。必要なら事前に受付した任意のPDFについて、ワークシートで
`REMOVE @SNOWVILLAGE_DB.SNOWVILLAGE_RAW.SNOWVILLAGE_PDF_STAGE/<受付ID>/original.pdf;` を実行してから「AIで読み取り」を押すと
FAILED になり、画面Dの「処理失敗」に計上されます（原本を戻せば再処理できます。テスト `test_50` と同じ手順）。
